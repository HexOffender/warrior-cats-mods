# How wcmods is organized: a review (October 2026)

A read-through of the repository as a player, a mod maker and a contributor would meet it, made
on 2026-10-26 at commit 17a5e0e (build 26184573 verified). It changes nothing; it says where the
organization has become confusing and proposes fixes, each small enough to be one pull request.
Line numbers are from that commit.

What was done: every document read; the code of the mod menu, Clan Mod Studio, onboarding and
the CLI read; the studio started from a fresh checkout (no `wcmods.json`, only the mod menu in
`mods/`) and every page opened in a browser; the CLI's `--help` and a first `status` run. The
game itself wasn't started.

**The short version.** The pieces are each well made and well commented. What has gone wrong is
layering: the same thing is explained, listed or named in several places, and the places no
longer agree. A player meets three surfaces (Clan Mod Studio, the mod menu, the command line)
with three vocabularies; a mod maker meets four lists of the mod menu's pages and three mod
folder layouts; a contributor meets 60 flat modules of which a third are Lua inside Python
strings. Most fixes are deletions and links, not new code.

## 1. The map: how it's organized now

### The repository

### The three surfaces a player meets

1. **Clan Mod Studio** (`python wcmods.py studio`): a side bar with two groups, **Your mods** (one
   page, Mods) and **Make mods** (Palettes, Your cat, Controls, Names, Game data, Save; Console
   with code mods allowed). The Mods page holds eight things in a column: Get set up, the
   game-update banner, the "not in the game yet" banner, Add a mod, Your mods, Options, Backups and
   repair, Make your own mod (`studio/sections/mods.js`, 607 lines, the largest page).
2. **The mod menu** in game (Insert): a side bar of eight groups, Home, Your cat, World, Story,
   Fight, Cheats, Mods, Tools, with 18 pages between them. The grouping is a `group` argument on
   `Menu.page` ranked against `Menu.groups` (`wcmods/menu.py:946-950`); pages from other mods
   land in Mods unless they name a group.
3. **The command line**: 33 subcommands in one flat `--help`, from `status` and `install` to
   `game signatures make` and `cpp ide`.

### Who the code is for

By responsibility, `wcmods/` splits into: the mod manager core (`cli`, `pipeline`, `mods`,
`modzip`, `config`, `onboarding`, `ingame`, `ue4ss`, `gamebuild`, `sdk`; 4.2k lines); the game's
file formats (`pak`, `iostore`, `kraken`, `oodle`, `cooked`, `csvdata`, `texture`, `png`, `bcn`,
`save`, `savejson`, `blake3`, `cityhash`, `binio`, `pe`, `x64`, `signatures` and more; 5.5k);
generators of in-game Lua (`game`, `menu`, `hostpages`, `world`, `draw`, `view`, `mouselook`,
`catlook`, `bridge`, `playstate`; 7.7k, of which about 7,250 lines are Lua text inside Python
strings); the studio server (`studio.py`); the agent and self-test (`agent/`, `selftest.py`); the
C++ SDK (`cppmods.py`, `sections/cpp.py`, `cpp_sdk/`). None of this grouping is visible in the
folder listing.

## 2. The mod menu

### What's confusing

**One feature, six names.** The feature is "the mod menu"; the mod is "Mod menu"
(`mods/mod-menu/mod.json`); the shared Lua module is `WCModsMenu`; the UE4SS mod that owns the
window is `WCModsMenuHost` (`wcmods/menu.py:17`); `hostpages.py:5` calls it "the menu host's
script"; the Tools group has a page titled "Menu" whose heading is "This menu"
(`wcmods/hostpages.py:737-738`). The code's own pointers don't resolve: `menu.py:5` and `:1060`
send the reader to `docs/SDK.md, "Mod menu"`, and SDK.md has no such heading (its section is
`` ## `WCModsMenu` ``, line 486).

**The settings moved, the comments didn't.** The menu's key, size, controller button and cheats
live in `mods/mod-menu/menu.json` now, and `ingame.py:1-12` says so correctly, with a `LEGACY`
table that migrates the old `wcmods.json` keys. But `menu.py` still says the opposite five times:

> `Insert (wcmods.json "menu_key") opens a window` (`menu.py:3`)
> `change wcmods.json ("menu_key") and install again rather than editing this.` (`menu.py:1055`)
> `SETTINGS.cheats (wcmods.json "cheats") says whether they start on` (`menu.py:1763`)

and `host_script`'s docstring (`menu.py:2043-2044`) too. The studio's API keeps the old names
(`menu_key`, `menu_scale` in `studio.py:221-222` and `mods.js:436-446`) while the file says `key`
and `size`, so a reader meets both vocabularies. `KEY_NAMES` is kept twice (`menu.py:2023`,
`mods.js:435`) and the size limits three times (`ingame.MENU_SCALES`, `menu.py:1528`,
`hostpages.py:742`).

**In-game text points at a studio control by a name it doesn't have.** The Cheats page says the
starting state is set in "(Clan Mod Studio, Mods page, In game)" (`menu.py:1953`) and the Menu
page says "use Clan Mod Studio (Mods page, In game)" (`hostpages.py:741`). The studio control is
the **Settings** button on the Mod menu's card (`mods.js:334`); nothing in the studio is called
"In game".

**Four hand-written lists of the pages.** `README.md:92-100`, `docs/SDK.md:530-540`,
`docs/scripting.md:420-447` and the Overview page's "What's where" (`hostpages.py:240-248`), plus
the group order declared again in `wcmods/agent/menu.py:17` and as a comment in
`cpp_sdk/include/WCMods/Menu.hpp:273`. They already disagree: the README says "**Mods:** pages
for mods with live settings" (`README.md:99`), but the two pages with live settings and a Save
button (Mouse look, Colours) are under Your cat; Mods holds script settings pages and ungrouped
pages.

**Two places called "mods".** The list of installed mods is a page under Home; the group named
Mods has no list, only other mods' pages.

**Three things called "console".** The Cheats page's "Console command" box runs engine console
commands (`menu.py:2007-2011`); the Tools page "Console" is a Lua console (its own heading says
"Lua console", `hostpages.py:909`); `python wcmods.py console on|off` and the studio's Options
toggle switch UE4SS's `ConsoleEnablerMod`, the game's `~` console (`ingame.py:23`). The README
puts that third one inside the mod-menu list: "**The game's console:** it's under Options on the
Mods page" (`README.md:116`), which is the studio's page.

**Mouse look sits in a different place on each surface.** In the mod menu it's under Your cat; in
the studio it's a card on the Controls page, which says "Saved in the Mouse Look mod; needs UE4SS"
(a mod from wcmods-examples the player may not have); in the README it's a file format
(`mouselook.json`, lines 434-474) that goes on to explain the camera actor's spring arm.

**Two mods can draw on one page.** `Menu.page(title, fn, opts)` uses the title as the id unless
`opts.id` is given (`menu.py:957`). Registration dedupes on id across Lua states
(`register`, `menu.py:936-942`), but each state's `tick()` renders every one of its own pages
whose id is the shown one (`menu.py:924-934`), so two mods that both call `Menu.page("Settings",
...)` share one tab and both draw into it each frame. Script mods are safe because `MOD.page`
sets `id = "script:" .. MOD.id` (`sections/scripts.py:133`); the SDK's example for other scripts
(`docs/SDK.md:551-564`) passes no id. Not reproduced in game; read from the code.

**Size.** `menu.py` is 2068 lines, of which 1,999 are Lua in two raw strings; `hostpages.py` is
926 with 855 of Lua, split off only "to stay under Lua's 200-local limit" and pasted into the
host at `@PAGES@` (`menu.py:2017`), where it uses the host's locals by name
(`hostpages.py:5-7`). Two of the host's pages (Nearby, Cheats) stayed behind in `HOST_LUA`. No
editor highlights or lints any of it; `luacheck.py` exists because "There's no Lua on the machine
to parse them" (`luacheck.py:3`) and checks brackets only.

### What's fine

The `group`/`order`/`id` model is simple and documented in `Menu.page`'s comment; the `ui.*`
row API (`menu.py:416-900`) is consistent; a `settings.json` becoming a page for free
(`sections/scripts.py:99-135`) is the right default; the Settings button on the mod's card is
the right home for its options.

## 3. Clan Mod Studio

### What's confusing

**The Mods page is the whole app.** Setup, updates, pending changes, adding, the list, options,
backups and repair, and making a new mod are stacked on one page, and the README sends people to
different depths of it ("Get set up, at the top of the page", "Backups and repair (at the
bottom)", "Options, below"). The two side-bar groups are lopsided: **Your mods** has one page.

**"Apply" is said three ways at once.** On a fresh checkout the top bar shows a chip "Not applied
yet", the Mods page shows a banner "Nothing is installed yet · Mod menu on · [Apply to game]", and
the top right shows "Apply to game" and "Apply and play". The code and the CLI say install; the
studio says apply; `docs/scripting.md:32` still says "Install (`python wcmods.py install`, or
Install in the studio)", a button that no longer exists.

**Every Make page saves into a different new mod.** The "Editing mod" drop-down on each page
defaults to its own: "My Palette (new)", "My Cat (new)", "My Controls (new)", "My Tweaks (new)",
"My Save Edits (new)". A player who touches each page ends up with five mods. The same drop-down
offers the built-in mod as a target: "Mod menu (no cats.json yet)", "Mod menu (no palette.json
yet)", and so on, so a palette can be saved into `mods/mod-menu/`, the one folder git doesn't
leave alone (`.gitignore`, `!mods/mod-menu/`).

**Pages contradict the README.** The Save page says "Not yet confirmed in game: The save has a
checksum whose formula isn't known" (`studio/sections/save.js`), while `README.md:598-601` says
"Edited saves load, and the game keeps the edits when it saves again; a Level change made with
the save editor was accepted." The Controls page's banner says "start it with `python wcmods.py
play`" (`controls.js:90`), though the studio's own Play button does that
(`onboarding.py:play`).

**The studio never links to the docs.** The player's main surface has no Help, no link to the
README or `docs/`, and refers to them as text: `README, "Remapping keys"` (`controls.js:90`),
`See README, "cats.json"` (written into every `cats.json`), `docs/scripting.md` (`console.js:30`).
The only outgoing links are to wcmods-examples and UE4SS on GitHub.

**Settings are in two places on one page.** The mod menu's options are behind its card's
Settings; the game console and "Allow mods that run code" are under Options further down; the
Console page appears in the side bar only after allowing code mods and a reload. Nothing says
that the three "console"s differ (section 2).

**Ids differ between the studio and the build.** Studio pages are `cat`, `save`, `console`,
`data`; the sections they write for are `cats`, `save`, `scripts`, `data`
(`studio.py:37-48`, `sections/__init__.py:20`).

### What's fine

The Apply/Play flow itself is right: Play applies what's waiting, the banner lists it, the game
has to be closed, and the log drawer shows what happened. The Get set up card is clear and does
the right things in the right order (`onboarding.py` docstring). The mod cards' notes
("Needs …", "Runs code, so …", "Made for an older version …") are the best copy in the project.
Pages load independently and one failing doesn't take the others down (`app.js:open`).

## 4. The docs

### What's confusing

**The README is five documents.** It switches audience without saying so: lines 1-54 are for
players, 55-89 pile the whole mod-maker surface into two paragraphs with five pointers into
`docs/`, 90-132 go back to players (the mod menu, cheats), 134-192 is a how-to that opens with a
test narrative ("That was tested twice: once with the mouse in the camera slots, and once with
keyboard keys only", `README.md:137-138`), 247-277 is for contributors, 278-556 is a file-format
reference that drops to reverse-engineering depth inside `mouselook.json` ("turning rotates the
camera actor's root. The game resets the spring arm's and the camera's pitch every frame",
`README.md:449-450`), and 570-672 is 86 lines of dated test logs ("Confirmed in game
(2026-10-23)", three "(2026-10-24)" sections, "(2026-10-25)", then a 20-line "Not yet confirmed"
list). Requirements come last, at line 674. Reading time is 40-50 minutes.

**No entry point for a mod maker or a contributor.** A player has a five-step quick start and is
done. A mod maker must infer from `README.md:76` and `:80` that `docs/scripting.md` comes before
`docs/SDK.md`; SDK.md's first 35 lines never say who it is for, opening with "The mod manager is
built from **sections**". A contributor's path starts 250 lines down under "How it's built".
There is no `docs/README.md`, no CONTRIBUTING, no architecture page.

**Pointers that don't resolve.** `README.md:82` sends readers to `docs/SDK.md, "Overlays"`; there
is no such heading (the material is `` ## `WCModsDraw` ``, SDK.md:441). `README.md:87-88` sends
them to `docs/SDK.md, "The game's own UI"`; SDK.md has only a bold run-in label by that name at
line 1007, while the heading `## The game's own UI` is in reverse-engineering.md:864. Most
cross-references are quoted heading names in prose rather than links, so they rot silently.

**Build numbers.** `gamebuild.VERIFIED_BUILD` is 26184573, and reverse-engineering.md:14-33 is
the one place that explains both builds. Five docs still present the old build as current:
"All of it is for Steam build 24847281." (`docs/mechanics/README.md:18`); "Everything on this page
was tried in game on build 24847281" (`docs/agent.md:16`, `docs/scripting.md:17`);
`docs/mechanics/combat.md:6`, `progression.md:128`. `docs/updating.md:34` shows
`"game_builds": [24847281, 24912345]`, an invented number beside a real one.

**Patch 1.1 left a contradiction.** reverse-engineering.md:26 says the patch "adds mouse control
of the camera"; `README.md:438-440` still says "the mouse never reaches its camera and no binding
can change that", and reverse-engineering.md:213-214 repeats it. Nobody says what is true on
26184573. (Mouse look stays, by decision; the docs should say why.)

**The same topic in several places, drifting.** The mod folder layout is in `README.md:315-321`,
`docs/SDK.md:37-65` and `docs/scripting.md:23-30`, and the `mod.json` keys differ between them:
the README omits `studio_title`, `studio_files` (SDK.md:41-44) and `settings_page`
(scripting.md:26). The shared Lua modules are "five" at SDK.md:11 and "six" at SDK.md:340 and
`README.md:263-265`. The built-in sections are eight in `README.md:249` and `SDK.md:3-5`, but
SDK.md's own table maps `items.json`, `scripts/` and `dlls/` to three more. Cheats are explained
in README 119-128, SDK.md 542-545 and reverse-engineering.md 651-661. Mouse look and the camera
are in README 434-474 and reverse-engineering.md 514-591, largely the same text.

**Stale against each other.** `README.md:642-643` says the menu's new pages "were checked with a
recording stand-in for the menu, not opened on screen" and `:652` lists them as not yet confirmed,
while `docs/agent.md:284-288` describes `test_menu.py`, which opens every page and photographs it.
"The pause menu hasn't been checked yet" appears twice (`README.md:161`, `:606`).

### What's fine

`docs/updating.md` is the model: it says in its first lines what it is, then has a heading per
audience. `docs/mechanics/README.md` is a good index page with a table and a method section. The
mechanics pages each state how every claim was confirmed. The module docstrings are uniformly
good; the problem is the names, not the comments.

## 5. Onboarding

### The steps as they are

1. Download the repository ZIP and unzip it.
2. Double-click `Clan Mod Studio` (a `.bat`). Without Python 3.10+, `wcmods/findpython.bat`
   offers a winget install or opens python.org, then asks for a second double-click.
3. The studio opens. On a machine where the game is installed, "Get set up" finds it, backs up
   the save and reports the loader; the player may never see the card. On a fresh checkout here
   the backup was made in the background with a toast ("Made a safety copy of your save") while
   another page was open, and `backups/20261026-…-first-run/` appeared.
4. If UE4SS is missing: "Install it" downloads `UE4SS_v*.zip` from the `experimental-latest`
   GitHub release (about 9 MB) and sets it up. The game has to be closed.
5. Download wcmods-examples as a second ZIP, drop it on the page, tick mods.
6. For any mod with code (the three complete examples the SDK promotes: game-tweaks, faster-run,
   quest-markers): find Options on the Mods page, tick "Allow mods that run code", confirm the
   warning, reload.
7. Press Play.

Seven steps and two third-party downloads is reasonable for a UE4SS-based manager, and each
message along the way is in plain language. The friction is in what happens when something is
off, and in the command line being a different product.

### What's confusing

**The CLI and the studio disagree about the same situation.** Without the game, the studio says
"Clan Mod Studio couldn't find it in your Steam games. In Steam, right-click … Browse local files,
and copy the address at the top of that window into here" (`mods.js:107`); the CLI says
"Couldn't find the game. Put its folder in wcmods.json as "game_dir"." (`cli.py:28`). Without
UE4SS, the studio says "Most mods need the script loader (UE4SS)"; `status` says
"not installed (needed for coat/pattern/marking colours)" (`cli.py:43`), which was true before
the mod menu existed.

**`wcmods.json` is undocumented.** It is the settings file the CLI tells players to edit, and no
page lists its keys. They are, from the code: `game_dir`, `save_dir`, `oodle_dll` (`config.py`),
`allow_code_mods` (18 sites), `allow_outdated`, `console`, `installed`, `installed_ue4ss`,
`installed_ue4ss_shared`, `debug_cat_look`, and the legacy `menu_key`, `menu_scale`, `cheats`
that `ingame.py` migrates away. The README mentions three of them in passing.

**Legacy names leak.** The UE4SS mod that carries wcmods' own scripts is still
`WCModsPalettes` (`config.py:11`, `UE4SS_MOD_NAME`), and the game-log reports it reads are tagged
`[WCModsPalettes]` (`ue4ss.py:252`), though it has long done colours, names, play state and more.

**"Get set up" is described as a place it isn't.** `README.md:12` says "Follow "Get set up" at
the top of the page"; it is a card under the Mods heading that shows only while a step is undone,
so a player who reads ahead looks for something that isn't there.

**The second repository is a step in disguise.** wcmods ships one mod. Everything a player would
want to try is in wcmods-examples, which the README introduces in step 4 as a second download and
the studio's Add card introduces as a link. That is a deliberate split (PR #14), but the
onboarding copy treats it as an aside.

## 6. The code layout

### What's confusing

**Sixty flat modules, grouped by nothing.** `ls wcmods` lists `accessories, bcn, binio, blake3,
bridge, catlook, cityhash, cli, colors, config, controls, cooked, cppmods, crashes, csvdata, draw,
eyeatlas, game, gamebuild, gamefiles, hostpages, ingame, iostore, keymap, kraken, luacheck, menu,
mods, modzip, mouselook, names, onboarding, oodle, pak, palettes, pe, pipeline, playstate, png,
recolor, remapper, save, savejson, sdk, selftest, signatures, studio, texture, ue4ss, view,
world, x64`. Names that don't say what they do: `x64.py` and `pe.py` (exe analysis for the
signatures); `draw.py`, `view.py`, `world.py` (generators of Lua overlay modules, not Python
drawing); `ingame.py` (the mod menu's settings) beside `game.py` (the `WCModsGame` Lua),
`gamebuild.py` (Steam build checks) and `gamefiles.py` (the file reader); `menu.py` beside
`hostpages.py` (more of the same menu) and `agent/menu.py` (driving it); `save.py` (the codec),
`savejson.py` (edits), `sections/savedit.py` (the section) and `studio/sections/save.js`;
`names.py` and `sections/names.py`; `controls.py` and `sections/controls.py`; `mouselook.py`
and `sections/mouselook.py`; `catlook.py`, `sections/cats.py` and `studio/sections/cat.js`.

**A third of the package is Lua in strings.** About 7,250 lines across 12 files: `game.py`
(2,068 in one literal), `menu.py` (1,031 + 968), `hostpages.py` (855), `draw.py` (501),
`world.py` (462), `mouselook.py` (390), `catlook.py` (232), `bridge.py` (185), `palettes.py`
(171), `view.py` (153), `sections/scripts.py` (114), `playstate.py` (53). They are templated by
`str.replace` on `@SETTINGS@`, `@KEY@`, `@PAGES@`, `@DATA@`. The only real `.lua` file in the
tree is the script template. No C++, JS or batch lives in strings; those are files already.

**Three things called "studio" and two called "tests".** `studio/` at the root (the front end),
`wcmods/studio.py` (the server), `wcmods/templates/` (what `wcmods new` copies; mods may also
ship a `studio/section.js`). `tests/game/` are in-game tests collected by `wcmods/agent/runner.py`
and run by `agent test`; `tests/kraken/` are fixtures read by `selftest.py`; there is no unit
test that runs without the game. The 47 checks that need no game (blake3, CityHash, CSV
round-trip, the save codec, PNG and BCn, pak and IoStore writers, the x64 decoder, modzip
refusals) are `check(...)` calls inside one function, `selftest.run`, and `cmd_selftest` calls
`ctx.need_game()` first (`cli.py:475`).

**Odd dependencies.** `onboarding.py:82` imports `cli._remap_plan`, a private function of the
CLI, while `cli` lazily imports `studio`, which imports `onboarding` (a cycle held open by the
lazy import). `cppmods.py:22` imports `sections.cpp` for three path constants and so loads the
whole `sections` package into the C++ build tool. `agent/window.py:14` imports `remapper` for two
ctypes structs, so the test agent depends on the key remapper. `cli.py` has 26 lazy imports and
no comment saying why.

**No project files.** No `pyproject.toml`, `requirements` (there are none; that is a feature
worth stating), `CONTRIBUTING.md`, `ARCHITECTURE.md` or CI. The only architecture text is
`README.md:247-277`, which lists eight built-in sections where there are eleven.

**Orphans.** `designer/palette-designer.html` (736 lines, titled "Clan Palette Studio") is
referenced by nothing but a comment in `palettes.py:190`; its `game-data.js` is gitignored and
no code writes it. `tools/re/uht.py` reads PE files on its own (98 lines) instead of using
`wcmods.pe`, and `callers.py`, `dispscan.py`, `storemap.py` each insert their own directory into
`sys.path`.

### What's fine

The format modules are cleanly layered (`gamefiles → iostore/pak → oodle → kraken`,
`texture → bcn/png/cooked`). The Lua generators import nothing but `lua_value`. `sections/` is a
real plug-in boundary with a documented base class and a loader that isolates a broken mod's
section. The agent package is self-contained.
