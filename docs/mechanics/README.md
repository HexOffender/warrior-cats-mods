# How the game's mechanics work

What we've worked out about the game's rules, one system per page. They're for building mods:
which numbers to change, what a change will do, and where the game itself is broken. The
engine-level findings (files, objects, the camera, cheats, UE4SS) are in
[reverse-engineering.md](../reverse-engineering.md), and the SDK in [SDK.md](../SDK.md).

## The main findings

- **Damage** is a Pokémon-style formula:
  `round(((Power × A × (1 + 0.5 × level)) / max(1, D × (5 + 0.3 × level)) + 2) × stance × 0.015 × (85..100))`.
  Read from the code; see [combat.md](combat.md#the-damage-formula).
- **Resilience may not reduce damage:** the code takes the defender's stat from the stance
  table's `Attack` column, and its `Defense` column isn't read. Needs a test in game.
- **Accuracy is a plain chance to hit:** −0.2 when Blinded, and no stat changes it.
- **Prowess is (very likely) health,** and combat stamina is 0.4 × Prowess + Stamina.
- **Stats grow** as base + growth × (level − 1) / 20. Social traits add to the growth: Brave gets
  +20 Strength and +10 Instinct growth (+19 and +9.5 at level 20), and so on. Checked against a
  level 20 save.
- **Trait bugs:**
  - The fresh-kill trait bonus checks for Curious and reads keys that don't exist, so no one gets
    it.
  - Patient's bonus rows are never read by the exe.
  - Curious's extra-consumable bonus works.
  - See [progression.md](progression.md#what-traits-do-in-play).
- **Data bugs:**
  - The Abundant fresh-kill Prowess bonus row is misnamed (`…Bonus.Abundantv`).
  - The Cobweb online gift is misspelt (`Materials.Cobweb`).
  - The Full Healing Herb recipe lists Heather twice.

## How these were worked out

- **The numbers** are the game's own data tables, extracted to
  `vanilla/Wrc/Content/Gameplay/DataTables/NonAsset/` (`python wcmods.py extract`), with
  English names from `Strings/NonAsset/Strings_EN.csv`.
- **The tables in these pages** are generated by `tools/re/mechanics_tables.py`. Run it again
  after a game update; it rewrites everything between `<!-- table:… -->` and `<!-- /table -->`.
- **The formulas** come from the exe:
  - `tools/re/xrefs.py` finds the code that loads a tuning key.
  - `tunemap.py` and `storemap.py` show which member each key goes to.
  - `dispscan.py` finds the code that reads those members back.
  - `callers.py` lists who calls a function.
  - `uht.py` reads enums and struct layouts.
  - The method is in [reverse-engineering.md](../reverse-engineering.md#how-we-find-things).
- **Checks against a real save** are noted where they were made.

**Not every tuning key appears in the exe.** About half of `TuningData`'s 441 keys aren't stored
anywhere as whole strings. Some are built from parts (`Gameplay.Exploration.Detection.%s`,
`Gameplay.Exploration.Level.<n>`), and others are presumably read by Blueprints. So a key missing
from the exe isn't proof that it's unused, but a key the code asks for and the table lacks (as
with the fresh-kill bonus) is a real bug.

**How sure each claim is:** every page says how each finding was confirmed, as "read from the
code", "matches the save", "seen in game", "from the tables" or "a guess". Add new findings the
same way.
